📖 О проекте
CryptoBot-RL — это исследовательский проект по созданию торгового агента для криптовалютных рынков. В основе лежат:

Сбор данных — парсер OHLCV-свечей с бирж Binance и KuCoin через библиотеку ccxt.

Торговая среда — кастомное окружение на базе gymnasium, поддерживающее мультитаймфреймы (15 минут, 4 часа, 1 неделя), технические индикаторы (RSI, ADX, BB, ATR, OBV) и гибкое пространство действий.

Агент — алгоритм PPO (Proximal Policy Optimization) с улучшенной архитектурой:

RMSNorm вместо Batch/Layer Normalisation для стабильности и скорости.

Transformer-блок с Multi-Head Attention и механизмом Mixture of Experts (MoE) в feed-forward слое.

Внешняя дифференцируемая память с операциями чтения/записи и механизмом забывания (на основе возраста и важности).

Проект задумывался как личный торговый бот, но стал полезной платформой для экспериментов с RL на финансовых данных. Здесь вы найдёте готовый парсер, гибкую среду и передовую архитектуру агента — всё это можно использовать как основу для собственных исследований.

✨ Особенности
Компонент	Описание
Парсер (parser_data.py, *.ipynb)	Загрузка данных с Binance/KuCoin, вычисление 6+ индикаторов, сохранение в форматах Parquet/Feather. Возможность парсить любые криптопары (не только BTC).
Среда (birja*.py)	Мультитаймфреймовое окружение, совместимое с gymnasium.Env. Настраиваемые окна наблюдения, глобальные признаки (временные метки), one-hot последнего действия, PnL. Поддерживает как локальные данные, так и потоковую загрузку через парсер.
Архитектура агента	PPO + RMSNorm + Transformer с MoE + External Memory — всё реализовано на TensorFlow/Keras.
Модульность	Все компоненты вынесены в отдельные файлы, легко модифицируются и расширяются.

text

Важно: пути к данным в parser_data.py и birja*.py прописаны жёстко (D:\Python1\AI\cripto_bot\...). Перед запуском замените их на свои директории.

⚙️ Установка и настройка
1. Клонируйте репозиторий
bash
git clone https://github.com/nikit172/crypto-bot-rl.git
cd crypto-bot-rl
2. Создайте виртуальное окружение (рекомендуется)
bash
python -m venv venv
source venv/bin/activate   # Linux/Mac
venv\Scripts\activate      # Windows
3. Установите зависимости
Все используемые пакеты и их версии перечислены в файле version.txt.
Установите их через pip:

bash
pip install -r version.txt   # если переименуете файл в requirements.txt
Либо вручную установите ключевые библиотеки:

bash
pip install tensorflow==2.18.1 keras==3.10.0 numpy==1.26.4 gymnasium pandas ccxt ta pyarrow feather-format jupyter
Остальные зависимости (matplotlib, seaborn, tqdm и т.д.) можно установить по мере необходимости — жёстких ограничений нет.

📊 Подготовка данных
Данные можно получить двумя способами:

Вариант А: Запустить парсер из ноутбука
Откройте parser.ipynb или parse_data.ipynb.

Выполните ячейки последовательно. Парсер загрузит свечи с Binance/KuCoin, вычислит индикаторы и сохранит .parquet файлы в указанную директорию.

Пример вызова в коде:

python
from parser_data import parse
parse(symbol='BTC/USDT', timeframe='15m', limit=1000)
Повторите для разных таймфреймов (15m, 4h, 1w), чтобы получить три файла (например, from_3_4.parquet, from_2_4.parquet, from_1_4.parquet).

Вариант Б: Использовать уже готовые данные (только BTC)
Если вы хотите сразу приступить к экспериментам без парсинга, вы можете запросить у автора готовые Parquet-файлы для BTC (свяжитесь через GitHub Issues). В будущем планируется добавить пример данных в репозиторий.

🚀 Запуск обучения
Основной ноутбук для тренировки агента — model copy 7_3.ipynb.
Порядок действий:

Убедитесь, что данные лежат в папках, указанных в birja1.py (или измените пути).

Откройте model copy 7_3.ipynb в Jupyter.

Выполните ячейки по порядку:

Регистрация среды в gymnasium (может выдавать предупреждения — это нормально).

Инициализация агента (класс PPOAgent из PPO_model2.py).

Цикл обучения.

Во время обучения модели будут сохраняться (путь сохранения задаётся внутри ноутбука).

Если среда не регистрируется — вы всегда можете использовать её как обычный Python-класс, импортировав TradingEnv из birja1.py или birja2.py.

🧪 Текущее состояние и ограничения
Что работает	Что не работает / требует доработки
✅ Парсер данных (любые пары, любые таймфреймы)	❌ Полноценное обучение — проблемы с градиентами и большим log_count
✅ Торговая среда (мультитаймфрейм, индикаторы, действия)	❌ Нет предобученных весов модели
✅ Архитектура агента (PPO, Transformer, MoE, память)	⚠️ Регистрация среды в gymnasium может требовать правок (но класс работает)
✅ Внешняя память с чтением/записью	⚠️ Проект не завершён, используется как экспериментальная платформа
